# Anson咖啡厅管理系统

基于 PHP + JSON 存储的轻量级内部运营系统，无需安装 MySQL。

## 功能模块

- **会员管理**：注册、编辑、查询、冻结/删除
- **会员自助查询**：姓名、手机号、学号任选两项，查询余额、积分等账户信息
- **消费登记**：录入消费金额，自动计算积分并升级等级
- **咖啡制作大屏**：管理员在员工管理中创建“咖啡师大屏”账号，登录后直接查看今日订单；每笔订单汇总展示不同饮品，可逐杯完成、重做，或对当日消费中的单杯办理退款。重做会在消费记录生成零金额记录，并把追加成本计入财务；退款会写入退款记录并同步调整原消费及会员账户。余额支付自动退回会员余额；现金、微信及支付宝退款需在原收款渠道实际退回
- **手机号待补全**：注册时手机号留空即标记为待补全，会员下次消费时提醒补全；填写手机号后按姓名和手机号实时查重
- **紧急公告**：首页及制作大屏用红框展示未读紧急公告，点击已读后隐藏
- **积分兑换**：支持兑换咖啡、甜点、优惠券等
- **数据统计**：会员总数、消费总额、积分分布、最近消费记录

## 环境要求

- PHP 8.0+（需启用 PDO SQLite 扩展）
- 无需数据库服务器（使用 JSON 文件存储）
- PHP cURL 扩展（用于激活码校验）

## 快速启动

```bash
cd examplepathway
php -S localhost:8080 router.php
```

浏览器访问：http://localhost:8080

会员自助查询页：http://localhost:8080/cq/

首次打开系统会先要求创建唯一的总管理员，然后由总管理员输入激活码。授权通过后才能进入业务系统。

初始化页面还会设置饮品与价格、会员等级门槛与折扣、消费积分比例，以及积分兑换开关和兑换项目。初始化完成后，总管理员可在“管理后台 → 系统设置”继续修改；会员等级折扣会用于消费结算。

总管理员还可以在“管理后台 → 系统设置”修改网站名称并上传 Favicon 网站图标，名称会同步用于导航品牌和浏览器页面标题。

## 激活码接口配置

授权客户端默认连接 `https://auth.ansonqu.com`，生产环境可通过 Web/PHP-FPM 的环境变量配置：

```bash
AUTH_API_BASE_URL=https://auth.ansonqu.com
AUTH_ACTIVATE_ENDPOINT=/api.php
AUTH_VERIFY_ENDPOINT=/api.php
AUTH_PROJECT_KEY=请填写授权站项目标识
AUTH_API_KEY=请填写授权站项目的API密钥
```

也可以在禁止 Web 访问且已被 Git 忽略的 `data/auth.php` 中保存 `project_key` 和 `api_key`。环境变量优先级更高，建议正式服务器仍优先使用环境变量。

客户端会向单一 API 入口发送 `action`、`activation_code`、`code`、`device_id`、`machine_code`、`project_key`，已激活后还会发送 `license_token`。API 密钥同时通过 `X-API-Key` 和 `Authorization: Bearer` 请求头发送。`AUTH_PROJECT_SECRET` 仍作为旧配置名兼容，但新部署请使用 `AUTH_API_KEY`。

## 每日授权校验

系统会在每天 23:00 后的首次页面请求自动校验。生产环境还应增加 cron，确保每天 23:00 准时执行：

```cron
0 23 * * * /usr/bin/php /网站绝对路径/cron/license_check.php >> /网站绝对路径/data/license-check.log 2>&1
```

远端明确返回授权无效时会立即锁定业务页面；临时网络故障不会直接锁死营业端，系统会每 15 分钟重试。

## 部署到生产环境

可将项目部署到 Apache/Nginx + PHP 环境：

- Apache：确保启用 `mod_rewrite`，将文档根目录指向项目根目录
- Nginx：配置 `try_files` 指向对应 PHP 文件
- 确保 `data/` 目录有写入权限，并禁止 Web 直接访问该目录
- 为 `cron/license_check.php` 配置每天 23:00 的计划任务
- 使用 HTTPS，并在服务器环境变量中保存项目密钥
- **接入 CDN 时**：请按 `CDN-DEPLOY.md` 配置缓存规则 —— 动态页面（*.php、/api/*）必须回源不缓存，静态资源（/assets/**）长缓存；系统已在代码层发送 `Cache-Control: no-store` 并识别 CDN 转发头获取真实客户端 IP

## 财务管理

管理员拥有完整财务权限。新增员工时可选择“财务”职位，并决定该账号是否同时拥有普通员工权限。财务模块包含经营看板、收支流水、支出管理、资金账户、会员储值负债、经营报表和 CSV 导出；收入直接取自消费及充值登记。退款不在财务模块内，而是与客诉一致：在“消费记录”页对应记录点「退款」，或在“退款记录”页发起，财务看板与收支流水仍会统计退款金额。

“每日收入上报”对普通员工、财务和管理员全部开放。系统会按上报日期自动计算各支付渠道的消费登记参考金额，每个账号每天可提交或更新一次自己的实报金额；财务和管理员可查看全部账号的上报及差异，普通员工只能查看自己的记录。上报备注同样采用加密存储。

消费记录支持发起客诉，可按原订单选择全部重做或部分重做，并可重新取号。完成后系统会生成金额和积分均为 0 的“客诉补偿”消费记录，不计入营业收入、每日上报或经营订单数。客诉内容及处理备注加密保存，管理员可在“管理后台 → 客诉记录”集中查看。

资金账户支持在现金、微信、支付宝、银行卡及已有账户之间进行资金划转。划转只调整账户估算余额，不计入收入、支出或利润；划转备注加密保存。页面不再允许新增自定义账户，已有账户和历史数据继续保留。

财务管理中的“成本记录”可先统一维护成分库（名称、计价单位和单价），再为每个菜单产品直接选择成分并填写单杯用量，系统自动加总单杯成本。成分单价和产品配方加密保存；消费结算会固化当时的商品成本。积分兑换直接选择实际商品并固化其配方成本；后台可自由添加或删除无实物兑换项目，为其自定义名称和固定积分。兑换页还会额外提供“其它”，只有选择“其它”时才需现场填写备注和积分。兑换成本不增加营业收入或销售订单数，但会计入商品成本并扣减净收入。积分兑换页会保留会员、商品、积分、成本、备注及操作人记录。后续修改配方不会改写历史记录。

新消费不再提供银行卡支付。会员消费由服务端强制使用会员余额；散客消费可使用现金、微信或支付宝。会员充值收款同样只提供现金、微信和支付宝。历史银行卡记录会继续保留用于旧账查询。

财务账户号、账户持有人、往来方、票据号、备注及退款原因使用 AES-256-GCM 加密保存。系统首次使用加密字段时会自动生成 `data/finance.key`（文件权限 0600）。也可以通过 `FINANCE_ENCRYPTION_KEY` 环境变量提供 32 字节密钥的 Base64 编码。部署和备份时必须单独安全备份该密钥；密钥丢失后，已有敏感字段无法恢复。

系统会在正常使用过程中自动创建缺失的 `data` 文件，并补齐新表、字段、职位属性和配置项，不需要单独执行升级或修补操作。
